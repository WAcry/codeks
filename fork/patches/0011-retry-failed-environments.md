# 0011 在新任务开始时重试失败的执行环境

```toml
watch_paths = ["codex-rs/core/src/environment_selection.rs", "codex-rs/exec-server/src/client.rs"]
watch_regex = ["activate_turn_environments|update_selections_with_bindings|TurnEnvironmentResolution"]
backport_of = []
upstream = []
ci_skip = []
```

## 背景

远端执行器在创建或恢复线程时不可达，环境初始化会把连接错误保存在共享 future 中。网络恢复后，底层客户端虽然可以重连，但新任务看到环境 ID、工作目录和根目录没有变化，会跳过环境更新，继续使用旧的失败结果。因此，同一线程下一次任务仍可能没有可用的执行环境。

这不是所有断线的共同表现。已经成功初始化的环境沿用现有连接恢复机制；能力目录发现也已有自己的传输错误重试。本补丁只修复任务开始时保留了失败初始化结果的路径。

## 改动

新任务激活环境时，先更新从线程继承的配置，再调用现有 `update_selections()`，不再因选择相等而跳过。该函数已经会复用健康初始化，并重新启动失败初始化。保留原有 active-task 检查和锁顺序，不在另一个任务执行期间切换环境。

涉及路径：

- `codex-rs/core/src/session/environment.rs`：移除相同选择时跳过更新的判断。
- `codex-rs/core/tests/suite/remote_env_retry.rs`：同一线程的远端初始化恢复测试，以及健康连接的握手和元数据请求复用检查。
- `codex-rs/core/tests/suite/mod.rs`：注册新测试模块。

环境 ID、工作目录、根目录和配置所有权保持原值。线程继承的配置继续从最新 defaults 推导；外部所有者提供的配置仍由原有 Ready、Pending、Failed 规则处理。本补丁不增加后台重试，不重放已执行的命令，也不添加 RPC。元数据请求失败后被上游降级成成功结果的情况不属于本次修改。

## 必要性

同一环境的暂时不可达不应要求用户另建线程或改换工作目录。客户端调用 `environment/info` 只能恢复连接，不能清除线程保存的失败初始化结果；取消订阅需要等待闲置卸载，归档会关闭子代理树，均不适合作为恢复动作。增加配置项或模型协议 bridge 也无法修复这个任务生命周期判断。

用户已授权采用独立的最小原生修复。这里直接进入上游已经具备的失败重试逻辑，比增加恢复接口或另一套重试状态更小。调查时最新上游主分支仍保留相同选择时跳过更新的判断，未找到可回移的等价已合并修复。

## 何时扩展

上游改变 `activate_turn_environments()` 的任务边界、`update_selections_with_bindings()` 的健康结果复用，或共享初始化结果的生命周期时，重新确认重试发生在下一任务开始前，并且不会覆盖外部所有者的配置。若另有证据表明元数据降级或能力目录缓存需要修复，单独评估，不把这些不同状态自动纳入本补丁。

## 何时移除

上游在同一环境的新任务开始前自动重试失败初始化，或不再缓存这类失败时，删除本补丁。以相同 ID、工作目录和根目录下的离线后恢复用例判断是否等价；仅连接层增加重连或提供状态查询还不够。

## 冲突处理

保留上游最新的任务检查、锁顺序和 defaults 更新，只确保相同选择也能进入已有的失败重试路径。不要复制环境解析器、另建连接或绕过 Ready、Pending、Failed 配置所有权。如果上游已合入等价行为，直接删除本补丁及测试。

## 验证

本地只运行 `codeks.py check`、`git diff --check` 和修改文件的 rustfmt；编译及回归测试由远端 `codeks-ci` 的 `codex-core` crate 执行。上游已有的 `replacement_environment_events_follow_selected_environment` 单元测试直接检查相同 workspace 更新会复用 shared resolution，新集成测试检查实际恢复及健康阶段无新增握手或元数据请求。

使用新构建时，先让注册的远端环境不可达并创建线程，恢复同一执行器后，在该线程中保持相同环境选择开始下一任务。检查命令确实在执行器运行，随后健康任务没有新增初始化握手或元数据 RPC。另检查持续离线时仍返回连接错误，外部所有者报告的配置失败仍需其提供有效配置。
