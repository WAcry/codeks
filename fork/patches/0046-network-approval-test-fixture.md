# 0046 稳定并发网络审批的测试时序

```toml
watch_paths = ["codex-rs/core/src/unified_exec/**", "codex-rs/core/src/tools/network_approval.rs"]
watch_regex = ["ExecCommandBegin|start_concurrent_network_requests|EARLY_EXIT"]
backport_of = []
upstream = []
ci_skip = []
```

## 背景

在 GitHub runner 上，并发网络审批测试可能在等待命令结束时超时。统一执行在报告命令开始前会短暂观察进程是否退出。过早批准时，响应较快的命令可能在这一阶段结束。测试随后等待命令结束事件才处理另一端口的审批，命令的输出收集则可能在等该审批结束。

## 改动

`codex-rs/core/tests/suite/network_approval.rs` 中的并发夹具同时等待初始审批事件和每条命令的 `ExecCommandBegin`，再提交第一个批准。保留三个配置入口、原有网络目标、审批决定、结束顺序、会话复用、SOCKS 请求及拒绝规则断言。

## 必要性

这些用例需要已启动的后台命令。等待执行服务发出的启动事件可建立该前提，无需通过增加等待时间或修改运行时权限稳定测试。

## 何时扩展

上游更改命令启动事件、早退观察、审批期间的输出收集或并发夹具时，复核测试等待的事件是否仍能确认后台命令已经启动。

## 何时移除

上游夹具保证在后台命令开始后才提交审批时，移除此补丁。

## 冲突处理

保留上游的命令启动和审批流程。仅在并发测试夹具上补充启动事件等待。

## 验证

在远端 CI 执行三个审批参数用例与并发拒绝规则用例。批准后的命令须先结束，独立端口随后才被拒绝，会话批准须跨轮次复用，SOCKS 审批须单独触发。
